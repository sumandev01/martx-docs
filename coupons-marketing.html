11.2 Dual Discount Mechanics: Percentage vs. Fixed Amount

MartX incorporates a high-performance, precision mathematical discount calculation engine engineered to handle diverse marketing campaign strategies. The platform natively provides two fundamentally distinct discount architectures: Percentage (%) and Fixed Currency Amount ($ / ৳).

Comprehensive Architectural Comparison: Percentage vs. Fixed
Architectural Metric 1. Percentage Discount (%) 2. Fixed Amount Discount ($ / ৳)
Deduction Method Relative mathematical ratio deducted from cart subtotal (e.g., 15%, 20%). Absolute flat monetary sum deducted directly from cart total (e.g., $10.00, $25.00).
Mathematical Formula Discount = Min(Cart Subtotal × Rate / 100, Max Discount) Discount = Min(Fixed Amount, Cart Subtotal)
Margin Protection (Cap) Mandatory Requirement
Requires Max Discount ceiling to stop enterprise margin loss on large orders. 		Disabled & Cleared
Fixed deductions are intrinsically self-limiting; maximum cap field is automatically disabled.
Qualifying Spend Barrier Enforces Min Order Amount to guarantee cart profitability before applying discount. Enforces Min Order Amount to ensure order subtotal significantly exceeds the flat deduction.
Ideal Marketing Play Sitewide seasonal blowouts, flash festivals, category sales (e.g., SUMMER2026). New customer welcome gifts, cart abandonment incentives, VIP retention (e.g., SAVE10).
Case Study A: Percentage Discount with Cap

Campaign Setup: Coupon SUMMER2026 grants 20% off on orders with a minimum spend of $75.00, constrained by a $50.00 Maximum Discount Cap.

  • Scenario 1 ($100 Cart): 20% of $100 = $20.00 discount. Customer pays $80.00.
  • Scenario 2 ($500 Cart): 20% of $500 = $100.00, but capped at $50.00. Customer pays $450.00. Store margin is protected!
  • Scenario 3 ($50 Cart): Rejected at checkout because subtotal is below the $75 minimum barrier.
Case Study B: Fixed Flat Amount Voucher

Campaign Setup: Coupon SAVE10 grants a flat $10.00 discount on orders with a minimum spend of $60.00.

  • Scenario 1 ($80 Cart): Flat $10.00 deducted. Customer pays $70.00 (12.5% effective savings).
  • Scenario 2 ($250 Cart): Flat $10.00 deducted. Customer pays $240.00 (4.0% effective savings).
  • Scenario 3 ($40 Cart): Rejected with explicit checkout notice: "Minimum order amount of $60.00 is required for this coupon."

Required • Numeric • Min 0 		The numerical value of the promotion. If Percentage is selected, enter the percentage integer (e.g., 20 for 20%). Below the input, dynamic helper text clarifies whether the amount is interpreted as a percentage or currency figure.
Min Order Amount * Number Input
Required • Numeric • Min 0 		The minimum gross cart subtotal qualifying threshold (e.g., 500). If a customer's cart subtotal before shipping is less than this value, the checkout engine halts application and prompts the customer to add more items to qualify.
Max Discount (For % Type) Dynamic Input
Required if Type = % 		The absolute financial ceiling on percentage savings (e.g., 200). When Percentage is selected, this field is automatically enabled and enforced by backend validation (required_if:type,percentage). If Fixed is selected, the input is disabled, greyed out, and cleared to prevent administrative confusion.
Total Coupon Limit * Number Input
Required • Integer • Min 0 		Global redemption quota across all customers combined (e.g., 100). Each successful order completed with this coupon increments the database counter. Once total redemptions reach this limit, the coupon automatically transitions to exhausted status.
Limit Per User * Number Input
Required • Min 1 (Default: 1) 		Maximum times an individual registered customer account may redeem this coupon. Setting this to 1 prevents voucher reuse by the same buyer, eliminating promotional budget exhaustion by single shoppers.
Start Date * datetime-local
Required • Date 		Chronological timestamp indicating when the campaign becomes eligible for checkout redemption. Attempted applications prior to this datetime are rejected with an advance notice.
Expire Date * datetime-local
Required • After Start Date 		Campaign cutoff timestamp. The server rigorously enforces after_or_equal:start_date validation. When the current server time surpasses this timestamp, the voucher code is rejected as expired.
Status * Select Dropdown
Active (1) / Inactive (0) 		Master operational switch. Defaults to Active. Selecting Inactive immediately suspends coupon usage across all customer carts without deleting the campaign entity.
Dynamic Client-Side State Machine in Action:

When you select Percentage in the Discount Type dropdown, the browser instantly enables the Max Discount input, marks it as required, and updates the helper note to: "Note: Discount will be applied as a percentage." Conversely, selecting Fixed disables and blanks out the maximum discount input, dynamically informing the operator: "Note: Amount should be in USD only."

11.4 Coupon Lifecycle & Revision Protocols (Edit Console)

The Edit Coupon console enables administrators to adjust ongoing campaign quotas, extend promotion dates, or pause underperforming vouchers. To protect audit integrity and ensure accurate historical invoice ledgers, MartX implements strict immutability barriers on core identifiers.

Admin Panel — Edit Coupon: SUMMER2026 — Promotional Revision & Quota Adjustments
Edit Coupon Form Interface (images/coupons/admin_coupon_edit.png)
Interactive Full-Screen Lightbox enabled. Click image or "Full View" to zoom. Coupon Revision Interface
Immutable Architectural Fields (Locked)

Once a coupon is generated, specific attributes are locked in the edit interface to protect store stability:

  • Coupon Code (readonly): Prevents altering the voucher string mid-campaign, which would break active banner ads, email promotions, and customer checkout sessions.
  • Discount Type (disabled): Prevents altering the computational paradigm (Percentage ↔ Fixed) on an existing voucher, eliminating accounting inconsistencies on past orders.
Mutable Operational Parameters (Editable)

Administrators can safely update operational parameters at any point during campaign execution:

  • Validity Period (Dates): Extend the Expire Date to prolong a high-performing campaign, or move it forward to end an expiring offer.
  • Usage Limits: Increase the Total Coupon Limit (e.g., from 150 to 300) when a campaign hits viral customer demand.
  • Emergency Status Toggle: Instantly switch Status to Inactive to pause redemption without deleting customer usage history.

11.5 Storefront Checkout Engine & Cart Valuation Pipeline

When a buyer enters a promotional code in the MartX storefront checkout modal (Apply Coupon), the backend executes a rigorous, zero-overhead atomic verification sequence before adjusting the payable subtotal.

7-Step Atomic Checkout Verification Sequence
1
Code Sanitization

Strips accidental spaces, normalizes case, and queries the database for active coupon records.

2
Temporal Validation

Verifies server timestamp lies within the start_date and expire_date window.

3
Global Quota Check

Evaluates current redeemed usage count against the usage_limit threshold ceiling.

4
Per-User Velocity

Checks buyer account redemption history against limit_per_user in coupon_usages.

5
Spend Barrier Check

Validates that gross cart subtotal meets or exceeds the required min_order_amount.

6 & 7
Deduction & Ledger

Calculates reduction, clamps to max_discount if %, updates cart totals via AJAX, and logs upon order completion.

11.6 Promotional Strategy & Marketing SOP

Deploy high-converting campaigns while safeguarding gross margins using MartX's enterprise coupon playbooks:

High-Converting Campaign Playbooks
  • First-Time Shopper Acquisition: Create a single-use coupon like WELCOME15 (15% off, min spend $50, max cap $30, limit per user = 1) displayed on welcome banners.
  • Seasonal Volume Drives: Launch codes like SUMMER2026 (20% off, min spend $75, max cap $50) for holiday weekends to boost basket sizes.
  • VIP Tier Incentives: Offer flat vouchers like SAVE10 ($10 off orders over $60) to reward repeat newsletter subscribers.
Fraud Prevention & Operational Safety
  • Always Mandate Per-User Limits: Keep Limit Per User set to 1 for standard public codes to block single buyers from claiming multiple discounts.
  • Always Define Max Discount on %: Never deploy an uncapped percentage coupon on high-ticket catalogs where a 20% discount could cause thousands in losses.
  • Pair with Expiration Timestamps: Always specify precise expire dates to prevent old promotional coupon links from circulating perpetually.
