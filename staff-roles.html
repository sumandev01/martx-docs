Chapter 19: Team Members, Staff & Granular RBAC Permissions

Architecting zero-trust administrative governance with Spatie-powered dynamic permission matrices, team showcase directory, automated staff onboarding workflows, and email-verified security protocols.

Granular RBAC Architecture

129+ granular permission nodes across 34 modules with fine-grained View, Create, Update, and Delete matrix controls.

Automated Staff Invitations

Frictionless onboarding with single-use invitation tokens, eliminating insecure plaintext password distribution.

Bank-Grade Profile Security

15-minute expiring cryptographic email verification tokens for administrator password alterations, preventing workstation takeovers.

Governance Architecture & System Path

As multi-vendor and enterprise commerce operations scale, maintaining strict boundaries between departments (Customer Support, Warehouse, Marketing, Catalog Management, and Finance) is essential. The MartX Administration Suite implements a rigorous Role-Based Access Control (RBAC) foundation built on top of the battle-tested spatie/laravel-permission package, augmented by automated audit trails, drag-and-drop team showcasing, and dual-layer email verification protocols.

Admin Navigation Paths:
• Admin Dashboard > Administration & Settings > Team Members
• Admin Dashboard > Administration & Settings > Role & Permissions
• Admin Dashboard > Administration & Settings > User Management
• Admin Dashboard > Administration & Settings > My Profile

19.2 Role-Based Access Control (RBAC) Architecture

MartX employs an enterprise-grade Multi-Tenant Role Matrix. Instead of hardcoded boolean permissions, access rights are dynamically evaluated through relational joins between roles, permissions, and authenticated sessions.

Admin Panel — Role & Permissions: Multi-Tenant Role Matrix
Roles Matrix
System Roles Classification & Immutability Rules

The MartX kernel strictly partitions roles into Protected System Roles (which cannot be deleted or stripped of root privileges to prevent administrative lockouts) and Custom Operational Roles.

Role Identifier Default Permissions Mutability Status Governance Function
Super Admin 129 Permissions Strictly Immutable Root system administrator. Has unrestricted access across all payment gateways, system settings, database migrations, and administrative user assignments.
Admin 118 Permissions Fully Mutable Store manager level. Grants daily operations control (orders, fulfillment, inventory, catalog, blogs) while restricting raw core infrastructure reconfigurations.
User 0 Admin Rights System Guarded Standard storefront customer account. Permitted only to view products, manage personal shopping carts, checkout, write reviews, and track order histories.
Custom Roles Configurable Full CRUD Store owners can create custom roles like "Inventory Clerk", "Content Writer", or "Support Agent" with precise module-level access.
Built-in Safety Shield: Accidental Lockout Protection

MartX includes an automatic safety lock on the primary Super Admin and customer User roles. These foundational roles cannot be deleted or stripped of their core capabilities by any staff member, permanently safeguarding your store against accidental lockouts.

19.5 Staff Onboarding, Profile Editing & Password Recovery

MartX eliminates the critical security flaw of administrators manually generating and texting passwords to new team members. Instead, the platform features a zero-knowledge Secure Email Invitation Pipeline.

Admin Panel — Invite & Add Team Member: Secure Email Onboarding
Staff Invitation
The Secure Staff Onboarding Lifecycle

When a store owner invites a new administrator or support specialist via Invite & Add New Team Member:

  1. The administrator specifies the user's official Email Address and selects an Assigned Role (e.g., Admin, Editor). Optional metadata like Full Name, Phone, and Avatar may also be pre-configured.
  2. Upon clicking Send Invitation & Create User, MartX dispatches a cryptographically signed invitation URL with a 24-hour expiration token.
  3. The recipient opens the email link and lands on a secure private onboarding page where they set their own confidential password. The admin never sees or handles their raw credential.
  4. The user account status switches automatically to Active, and their email address is marked as verified.
Admin Panel — Edit User Details: Password Reset & Verification
User Security
Administrative Password Reset & Email Verification Triggers

From the Edit User Details console, administrators have two one-click support tools for assisting locked out or newly registered users:

Send Password Reset Link

Generates a standard Laravel Password::createToken($user) valid for exactly 60 minutes. The reset link is emailed directly to the user with zero manual password input required from the admin.

Token Expiry: 60 mins
Send Verification Link

For users displaying the yellow Unverified badge, clicking this button creates a 60-character verification token in Redis/Cache valid for 24 hours and emails a verification link.

Token Expiry: 24 hours

19.6 Admin Profile Security & 15-Minute Verification Protocol

To protect against physical shoulder-surfing and unattended workstation takeovers, MartX features a Bank-Grade Email-Verified Password Protocol for all administrative accounts.

Admin Panel — Account Security: 15-Minute Re-Authentication Protocol
Profile Security
Dual-Card Architecture & Security Protocol
Card 1: Personal Information
  • Profile Image: Square photo (JPG, PNG, WebP) up to 2MB. Old files are automatically purged from storage/users/ upon replacement.
  • Full Name: Required admin display name across activity logs.
  • Email Address: Locked Immutable for active sessions to prevent email hijack vectors.
  • Assigned Role: Read-only Managed exclusively by root Super Admins.
  • Contact Details: Optional Phone Number, Gender selector, and Date of Birth date picker.
Card 2: Security & Password Protocol
  • Password Fields: Current Password *, New Password * (min 8 chars), and Confirm New Password * with show/hide eye toggles.
  • 15-Minute Token TTL: Clicking "Send Password Verification Link" hashes the new password and holds it in cache under admin_pwd_change_{token} for exactly 15 minutes.
  • Out-of-Band Email Confirmation: A verification link is dispatched to the admin's verified email. The password will NOT change until the email owner clicks the verification link.
  • Global Session Termination: Once confirmed, the system immediately invalidates all active sessions across all devices, requiring re-authentication with the new password.
Enterprise Staff Governance & Security SOP
Security Dimension Operational Rule Implementation Details
Least Privilege (PoLP) Enforced Never assign the root Super Admin role to contractors or department leads. Create dedicated custom roles granting only the exact CRUD operations necessary.
Employee Offboarding Instant Revocation When staff depart, set their account status to Suspended from the User Management console. Suspended accounts are barred at middleware level with instant session termination.
Self-Lockout Shield Automated Guard Logged-in administrators are forbidden by backend middleware from deactivating their own active account, preventing accidental total system lockout.
Auditable Event Logs Timestamped Every role reassignment, permission update, and profile modification is recorded with authenticated admin IDs and UTC timestamps in the database audit log.
